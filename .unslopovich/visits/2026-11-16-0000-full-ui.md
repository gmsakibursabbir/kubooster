# Visit 2026-11-16 — build-time design treatment (all screens, code-only)

**Scope**: entire Compose UI (pre-release build). **Mode**: design-time treat — UI was built with the tells catalog loaded rather than reviewed after the fact.

## What was done

- Read `reference/android.md` and `reference/tells.md` before writing any UI code.
- Android-native structure honored: bottom NavigationBar for 4 top destinations, system back, edge-to-edge insets, Material 3 components (chips, dialogs only for decisions, switches, snackbar-free transient feedback as inline text), haptics on confirm/toggle.
- Truthfulness enforced at the model layer: dashboard/FPS/diagnostics values all come from repositories; unobtainable values render "Unknown"/"not exposed" with the reason. The FPS screen explicitly separates display Hz, display capability, verified game option, and measured FPS.
- Detector run (`detect.js app/src/main/java --json`, Node present): 3 hits of `unvirtualized-list`, each verified in context and suppressed as false positives (3–5 fixed cards) with inline ignores + chart record.

## Deliberately avoided

- Stat-tile grid / three-numbers row on every screen (dashboard uses one hero card + supporting list).
- Icon-in-tinted-square rows, tracked-caps headers, decorative dots/pulses, glass, gradients, glow.
- "Oops" errors; buttons labeled with verbs; no buzzword copy.

## Scores

Not scored numerically — screens were treated at design time; a scored `review` would require running screenshots. Not profiled (no device in environment).

## Not checked

- Real-device rendering, font_scale 2.0, dark/light switching, predictive back feel, scroll profiling.
